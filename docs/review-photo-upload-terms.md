# 공개 리뷰 사진 업로드 이용조건 전환

## 정책과 구현 경계

이 문서는 기존 3단계 사진별 판정과 4단계 선택 동의 UI를 업로드 이용조건으로 전환한 현재 계약이다. 과거 문서는 당시 구현 기록으로 보존한다. 사용자가 이번 정책 변경과 신규 migration 작성을 승인했다. 이미 적용된 V20261102_004/V20261102_005는 변경하지 않는다.

사진 업로드는 공개 리뷰 및 여행지 메인 갤러리 활용에 필요한 비독점적 서비스 내 이용허락을 수반한다. 저작권은 회원 또는 원 권리자에게 남는다. 게시·복제·표시 크기 조정·관리자 승인 갤러리 노출에 한정하고, 해당 리뷰가 공개·유지되는 동안 적용한다. 사진/리뷰 삭제를 금지하거나 무조건 영구 보유하는 조항이 아니다. 외부 광고·제3자 제공·별도 상업적 재사용은 포함하지 않는다.

회원가입의 별도 필수·선택 사진 동의는 없다. 일반/소셜 가입은 같은 가입 정책 서비스를 사용하며 서비스 약관·개인정보 필수 동의 및 버전 충돌 검증은 유지한다. 사진 조건을 원하지 않으면 사진을 첨부하지 않고 일반 리뷰를 작성할 수 있다. 개인정보 처리 동의 이력으로 콘텐츠 이용허락을 대신 기록하지 않는다.

## 기존 코드 재사용

- `PHOTO_UPLOAD_NOTICE` 정책 종류를 업로드 이용조건으로 재사용한다. `GalleryConsentService`가 게시·시행 중인 실제 약관과 번역을 검증하고, 기존 `PolicyController`가 `/review-photo-terms`의 HTML/JSON을 제공한다. 특정 과거 게시 버전의 전문도 열람할 수 있다.
- 기존 작성·수정·사진 추가 API에 `photoUploadPolicyVersionId`를 전달한다. 실제 새 파일이 있는 경우만 현재 정책 ID를 검증한다. 조건이 누락·변경되거나 본문이 확인되지 않으면 409로 사진 저장을 거절한다. 파일 없는 리뷰 및 기존 사진 유지/삭제에는 새 이용조건 근거를 요구하지 않는다.
- 회원 잠금 이후 동일 트랜잭션 안에서 신규 사진의 근거를 검증한다. 정책 ID와 DB 벽시각을 새 사진에 저장하고 PENDING으로 만든다. 파일 저장/DB 실패 시 기존 cleanup/rollback을 유지한다. 소속·회원·여행지 잠금과 관리자 권한 검증도 유지한다.
- 프런트는 사진 입력 옆의 상시 안내와 실제 약관 버전·전문 링크를 사용한다. 가입/로그인 팝업이나 마이페이지 별도 동의 체크박스는 없다. 409 뒤에는 안내만 갱신하고 자동 재제출하지 않는다. 새 모듈도 기존 importmap의 내용 해시 경로를 사용한다.

## 신규/과거 사진 근거 분리

`V20261106_001__add_review_photo_upload_license.sql`은 nullable `gallery_license_policy_id`와 `gallery_license_accepted_at DATETIME(6)`을 추가한다. 이 ID는 실제 `policy_versions` 원본을 참조하며 시각은 `LocalDateTime`으로 DB 벽시각을 보존한다. 기존 행은 모두 NULL로 남기며 어떤 사진도 역기입·자동 승인 대기 전환하지 않는다. 기존 사진 상태·동의 이력·버전·시각·원본 이벤트 ID는 그대로 유지한다.

공통 `canonicalPhotoConsent`는 다음 두 경로를 분리한다.

1. 신규 이용조건 사진: 원래 PHOTO_UPLOAD_NOTICE 버전과 게시·시행·수락·사진 생성 시각, 새 근거 ID/시각 및 기존 스냅샷과의 혼합 여부를 검증한다. 회원의 REVIEW_GALLERY 동의 여부를 요구하지 않는다. 업로드 이후 새 약관이 생겨도 과거 사진을 그 새 버전의 이용범위로 바꾸지 않는다. 이 판정은 기존 서비스 내 게시·갤러리 기능에만 적용되며 외부 이용권을 뜻하지 않는다.
2. 과거 선택 동의 사진: 기존 원본 이벤트·버전·기준·철회 경계 판정을 유지한다. 과거 NONE/REVOKED는 새 조건이 생겨도 복구하지 않는다. 기존 REVIEW_GALLERY 정책과 번역을 덮어쓰거나 비활성화하지 않아 적법한 기존 허가를 일괄 무효화하지 않는다.

두 경로 모두 현재 회원 ACTIVE, 공개 여행지, 공개·미삭제·미차단 최상위 리뷰 조건을 사용한다. 승인만 메인 갤러리에 노출하며 필터를 LIMIT 앞에 적용한다. 관리자 사진 우선·회원 사진 정렬을 유지한다. 이후 갤러리 탐색 확장에서 총 30장 상한을 제거하고 한 번에 최대 30장씩 커서 조회하도록 변경했다(`docs/destination-gallery-paging.md`). 이용허락 판정은 그대로이며 승인·대표 유지·우선순위 Java 경로도 공통 권한 판정에 의존한다.

새 선택 동의를 수집하는 `/mypage/gallery-consent` GET 및 AGREE/DECLINE/LATER는 종료한다. 과거 허가의 철회권을 보존하기 위해 기존 인증·CSRF·버전 검증 PUT의 WITHDRAW(기존 agreed=false 포함)만 유지한다. 이 철회는 과거 선택 동의 사진만 처리하고 신규 이용조건 사진에는 적용하지 않는다. 신규 사진의 공개 중단은 기존 사진/리뷰 삭제 및 공개 제한 정책을 따른다. 과거 미동의 사진에 대한 추가 허가 UI는 이번에 만들지 않는다.

## Migration 적용 및 DEV 확인

새 migration은 두 컬럼, 원본 정책 FK/근거 CHECK, 기존 심사 상태 CHECK의 두 근거 허용, 신규 PHOTO_UPLOAD_NOTICE 버전과 5개 언어 번역을 추가한다. FK가 ON DELETE SET NULL인 과거 gallery_consent_id를 새 CHECK에 넣지 않는다(MySQL 제약). 새 정책 FK는 RESTRICT로 과거 근거 원문 삭제를 막는다. 스키마 reference는 적용 완료로 미리 갱신하지 않는다.

DDL은 여러 문장이라 migration 전체 rollback을 기대하지 않는다. DEV 적용 전 앱/배치의 관련 쓰기를 중지하고 백업한 뒤 사용자가 기동해 적용한다. 실패하면 최초 오류, 실제 컬럼·FK·CHECK와 Flyway 이력을 먼저 확인한다. 일부 성공 상태에서 파일을 임의 변경하거나 repair/재기동을 반복하지 않는다. 기존 .004/.005 checksum도 유지되어야 한다.

실기 확인: 새 회원/기존 동의·거부·철회 회원 모두 현재 조건의 새 파일은 PENDING, 파일 없는 리뷰는 조건 조회 장애에도 이용 가능, 관리자 승인/반려/그룹/우선순위, 과거 NONE/REVOKED 불변, 원본 리뷰 공개 유지, 리뷰 삭제·숨김·비공개·탈퇴 후 갤러리 제외, 일반·소셜 가입의 필수 약관 정상 동작. DB/JDBC 시간대와 실행계획·대량 데이터는 DEV에서 추가 확인한다. 자동 검증은 실제 DB에 접속하지 않는다.

## 검증 결과와 주요 변경 파일

- compileJava·bootJar·git diff --check 통과. 최종 관련 Java 테스트 723개는 실패 0건, 건너뜀 1건(기존 Windows 심볼릭 링크 갤러리 읽기 테스트)이다. 일반/소셜 가입·로그인·업로드·심사·갤러리·탈퇴·파일 정리를 포함한다.
- JS 단위 테스트 12개 통과. Chrome은 실제 MVC 리뷰 폼과 운영 CSS/JS에 API fixture를 사용해 360/390/393/430/768/1440 폭의 작성·수정·사진 선택·버전 전송·글만 수정 시 무소급을 검증했다. 기존 관리자 그룹/일괄/자격 제한/충돌 흐름도 같은 여섯 폭에서 통과했다. 실제 외부 로그인이나 DB 저장 검증은 아니다.
- 회원 동의로 잘못 설정된 정책을 업로드 이용조건으로 허용하지 않도록 서비스와 SQL의 플래그 조건을 일치시켰다. 신규 라이선스만 가진 사진의 승인·대표 유지·우선순위 회귀를 RED→GREEN으로 확인했다.
- 실제 렌더링에서 이용조건 전문 CSS와 새 uploadTerms 모듈의 내용 해시, HTTP 상태와 Content-Type을 확인했다. JAR의 새 migration·Mapper·템플릿·JS가 소스와 일치하며 퇴역한 팝업 CSS/JS/fragment는 포함되지 않는다.
- V004 checksum 847444896, V005 checksum -1439967468은 유지한다. 새 V20261106_001 migration은 정적 검토와 계약 테스트만 수행했으며 실제 적용은 미확인이다.

주요 범위: GalleryConsentService/PolicyConsentService/SignupPolicyService, PolicyController/GalleryConsentController, DestinationCommentService/ReviewImageService/ReviewGalleryPriorityService와 기존 작성·수정·추가 Controller, DestinationCommentImage 모델 및 사진·동의 Mapper, detail/layout/mypage/signup 템플릿, comment/events.js·api.js·uploadTerms.js, 해당 Java/JS 테스트. 기존 3/4단계 문서는 과거 기록으로 표시해 보존했다. 새 DB 테이블이나 별도 사진 관리 시스템은 만들지 않았다.

## 과거 선택 동의 철회 접근 경로 보완

전환 직후에는 과거 WITHDRAW API만 남고 사용자 화면의 접근 경로가 없었다. 내 리뷰 사진 관리(`/mypage/review-images`)에 과거 REVIEW_GALLERY 긍정 동의가 있는 본인에게만 철회 패널을 제공한다. 최신 DECLINE은 과거 허가의 전체 철회가 아니므로 최신 결정이 아니라 실제 마지막 AGREE(과거 action=NULL, agreed=true 포함)를 한 건 조회한다. 거부 이력만 있거나 신규 PHOTO_UPLOAD_NOTICE 사진만 등록한 회원에게는 패널을 보여주지 않는다.

이미 그 동의 이후 명시 WITHDRAW가 있으면 완료 상태만 표시한다. 거절 또는 의미 불명인 과거 false를 명시 철회로 허위 변환하지 않는다. 일반 사진 삭제는 기존 기능을 그대로 사용한다. 새 동의·재동의·가입 체크박스·로그인 팝업은 복구하지 않으며 종료된 GET 동의 API도 다시 열지 않는다.

철회 버튼은 원래 동의의 정책 ID·버전으로 기존 PUT을 사용한다. 정책이 비활성화돼도 원래 이용허락을 철회할 수 있다. 서버는 활성 회원 행 잠금, 본인의 실제 긍정 동의 및 정책 종류를 다시 검사하고 같은 철회는 중복 기록하지 않는다. 실패하면 성공으로 표시하지 않고 취소·중복 클릭·네트워크·세션 만료·409를 구분해 안내한다. 성공 후 목록을 새로 읽어 심사 상태를 반영한다.

과거 허가 철회는 기존 트랜잭션과 revokeGalleryImages를 재사용한다. 이 SQL의 본인 조건, `gallery_license_policy_id IS NULL`, PENDING/APPROVED/REJECTED 범위는 변경하지 않는다. 따라서 과거 사진만 REVOKED가 되고 원본 리뷰 사진·파일·원래 동의 ID/버전/시각은 보존한다. 신규 이용조건 사진의 근거와 승인 상태, 과거 NONE/기존 REVOKED는 변경하지 않는다. 어떤 migration도 변경하지 않는다.

브라우저는 실제 MVC 렌더링과 내용 해시 CSS/JS에 로컬 HTTP 응답 fixture를 사용해 360/390/393/430/768/1440 폭의 성공·취소·충돌·인증 오류·철회 완료·무이력 36개 사례를 확인했다. 390/1440 화면도 확인했으며 가로 넘침이 없었다. 실제 앱·DB 저장 검증은 아니므로 DEV에서 과거/신규 사진 혼합 회원의 상태와 원본 리뷰 공개를 추가 확인한다.

후속 검증: 핵심 Java 회귀 222개, JS 15개 통과. compileJava·bootJar·git diff --check 통과, JAR의 마이페이지 템플릿·JS/CSS·Mapper가 소스와 일치함을 확인했다. V004/V005/V20261106_001은 작업 시작·종료 SHA-256이 일치해 미변경임을 확인했다. DB 접속·SQL 실행·commit/push는 수행하지 않았다.
